# CLAUDE.md

## О проекте

**Quadruple** — Java-библиотека для вычислений с плавающей точкой четверной точности
(128-битная мантисса, 32-битная экспонента; чуть точнее стандартного IEEE-754 quadruple).

- Maven, groupId `com.mvohm.quadruple`, artifactId `Quadruple`, версия 1.2.0, Java 17.
- Основной класс: `com.mvohm.quadruple.Quadruple` (`src/main/java/com/mvohm/quadruple/`).
- Экземпляры **мутабельны**: `q1.add(q2)` меняет `q1`; есть и статические варианты (`Quadruple.add(q1, q2)`).
- Класс условно потокобезопасен: модифицирующие операции над одним экземпляром из разных потоков небезопасны.
- Документация API: https://m-vokhm.github.io/Quadruple/src/main/javadoc/com/mvohm/quadruple/Quadruple.html
  (локальная копия — `src/main/javadoc/`).

## План работы над тестами (задача 1)

Структура:
```
src/test/java/com/mvohm/quadruple/
  *Test.java     — тестовые классы (в пакете com.mvohm.quadruple: доступ к package-private)
  testdata/      — наборы данных (constants/, generators/)
  testutil/      — эталонные вычисления (ExactValue, BigDecimal), проверка точности,
                   адаптер форм вызова арифметики (BinaryOperation × CallForm)
```

Классы: `CreationTest` (конструкторы, кроме строкового), `AssignTest` (`assign(...)` со всеми типами,
в т.ч. на «грязном» экземпляре; `assign(String)`/`assign(BigDecimal)` отложены — у них свои нюансы),
`StringParsingTest`, `ConversionTest`,
`ToStringTest`, `ComparisonTest`, арифметика по операциям (`AddSubTest`, `MultiplyTest`, `DivideTest`),
`SqrtTest`, `SpecialValuesTest`, `ConstantsTest`, `ThreadSafetyTest` (`@Tag("slow")`).

- Арифметику делим по операциям, а не instance/static: один набор данных прогоняется через все формы вызова
  (экземплярная, статическая, с аргументами long/double) через адаптер; позже туда же — immutable-вариант.
- **Точность:** проверяем не относительную ошибку, а правильность округления: результат должен совпадать
  с правильно округлённым значением; если точное значение ближе к середине между соседними представимыми
  значениями, чем ε ulp, допустим любой из двух соседей (шум из-за конечной точности внутренних вычислений).
  - Округление везде (арифметика, субнормальные) — half-up по модулю (ties away from zero).
  - Арифметика: эталон `testutil/ExactValue` (точное ±M·2^E на `BigInteger`, `round()` даёт соседей и
    offset от середины), проверка — `QuadAssert.assertCorrectlyRounded(actual, exact, ε, context)`.
    ε = 0 для add/sub/mul (точные) и для divide (округление по точному сравнению удвоенного остатка с делителем,
    проверено на частных ближе 2⁻¹⁴⁰ ulp к середине); sqrt — пока 2⁻³², уточнить.
  - Преобразования String/BigDecimal ↔ Quadruple: эталон на `BigDecimal` с ограниченной точностью
    (на 10–20 порядков точнее тестируемой), ε — по javadoc плюс запас на неточность эталона.
    Ошибку мерить в ulp результата (ulp нижнего соседа), а не относительно значения.
    `BigDecimal.pow(n, mc)` принимает |n| ≤ 999 999 999 — степени 2 до 2³¹ считать в два приёма.
    Для перевода Quadruple → BigDecimal в эталоне не использовать тестируемый `bigDecimalValue()`.
- Случайные данные: свой `Random` с фиксированным seed на каждый набор; распределение по битам/экспоненте,
  а не равномерное по диапазону. Объём — через системное свойство (быстрый прогон по умолчанию).
- Падающие тесты не подгонять: `@Disabled("BUG-xx ...")` + запись в `KNOWN_ISSUES.md` (в корне, коммитится; вход для задачи 4).
- Порядок: перенос → генераторы → Creation → AssignTest → testutil (ExactValue) →
  Conversion → Comparison → SpecialValues → Arithmetic → Sqrt → StringParsing/ToString.

## Структура

- `src/main/java` — код библиотеки.
- `src/test/java/com/mvohm/quadruple/test` — старая подсистема тестирования.
- `src/test/java/com/mvohm/quadruple/*Test.java`, `testdata/` — новые JUnit-тесты.
- `KNOWN_ISSUES.md` — подтверждённые баги (BUG-xx).
- Ветка `newTests` — разработка новой подсистемы тестирования на замену старой.
- Зависимости тестов: JUnit 5, AssertJ; бенчмарки — JMH.
